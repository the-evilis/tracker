## Что это

Одностраничное приложение (PWA) из трёх файлов: `index.html` (разметка),
`app.js` (вся логика, ~3300 строк) и `styles.css`. Ванильный JS без сборки —
`deploy.sh` просто копирует файлы. Данные и авторизация — во внешнем облачном
Supabase `bjqcjktdbjgmwxcddppq.supabase.co`, таблицы `habits`, `user_settings`
и `transactions`, вход по email-коду и через Google.

Внизу пять разделов: **Focus** (цели с задачами и список «100»), **Money**
(доходы, расходы, графики), **Tracker** (привычки — прежний основной экран),
**Credo** (принципы) и **Quotes** (цитаты). Первые четыре раздела кроме денег
хранятся JSON-строками в `user_settings` (ключи `goals`, `list100`, `credo`,
`quotes`) — схему базы под них менять не пришлось. Операции лежат в отдельной
таблице `transactions`: их много, их нужно фильтровать по датам и складывать.
Отметки принципов пишутся в `habits` тем же ключом `год/месяц/день/<id>`,
что и привычки, поэтому серии и офлайн-очередь работают для них даром.

Живёт на **https://tracker.fountaine.online** — VPS 152.42.129.14 (Ubuntu, root
по SSH-ключу), статика из `/opt/tracker/public`, отдаёт nginx. Отдельного
systemd-сервиса и порта у проекта нет.

## Важные особенности, которые легко нарушить

**Формат ключа отметки.** Строка в `habits` имеет `id` вида
`год/месяц/день/<id привычки>`, например `2026/8/3/legacy-0`. Месяц с нуля, как
в JavaScript. Раньше в ключе стоял номер привычки в списке, из-за чего удаление
или перетаскивание сдвигало всю историю на соседнюю привычку. Привычки,
перенесённые со старой версии, имеют id `legacy-N` по прежнему номеру — за счёт
этого миграция детерминирована, идемпотентна и работает без сети
(`migrateLocalKeys`, `ensureHabitIds`). **Не меняй формат ключа и логику
миграции без крайней необходимости.**

**Снятая галочка удаляет строку**, а не пишет `done:false`.

**Числа количественных привычек** (цель «8 стаканов») хранятся не в `habits`, а
отдельным JSON в `user_settings` под ключом `values` — колонка `done` в базе
булева, и схему менять не пришлось.

**График привычки** живёт в поле `schedule`: `{type:'daily'}`,
`{type:'weekdays', days:[1,3,5]}` (0 = воскресенье) или
`{type:'times_per_week', n:3}`. Серии и проценты считаются от плановых дней, а
для «N раз в неделю» — в неделях. Смотри `habitSchedule`, `isPlannedDay`,
`getStreak`, `getMonthPct`.

**Клиент Supabase не бросает исключение** при ошибке запроса — он возвращает её
в `res.error`. Поэтому `try/catch` вокруг запроса ловит только сетевые сбои,
а `res.error` нужно проверять руками, иначе неудачное сохранение выглядит
успешным.

**Очередь офлайн-отметок.** `saveEntry` при сбое кладёт ключ в очередь
(`queueAdd`), а `flushQueue` досылает при возврате сети, возврате на вкладку и
старте. `loadData` не затирает ключи, лежащие в очереди. Не ломай это: без
очереди отметки, сделанные без сети, терялись навсегда.

**RLS в Supabase включён и проверен** — анонимный запрос с публичным ключом
возвращает `[]`, запись отклоняется. Ключ в HTML публичный по дизайну, скрывать
его бессмысленно.

## Деплой

```bash
ssh root@152.42.129.14
/opt/tracker/deploy.sh
```

`deploy.sh` делает `git reset --hard`, то есть **перетирает всё, чего нет на
GitHub**. Порядок всегда такой: правка → коммит → пуш в `main` → деплой. Правки,
залитые в `public/` напрямую, скрипт сотрёт.

На сервере также стоят по cron: `keepalive.sh` в 04:17 (free tier Supabase
усыпляет проект после 7 дней без запросов) и `backup.sh` в 03:40 — второй
пропускается, пока в `/opt/tracker/.env` не задан `SUPABASE_DB_URL`.

## Как проверять изменения

В логике много арифметики с датами, поэтому она покрыта тестами, которые
вытаскивают функции прямо из `index.html` и запускают в node без DOM:

```bash
npm test                                 # все проверки логики разом, 165 штук
node tests/test-logic.js    index.html   # миграция ключей, экранирование (36)
node tests/test-schedule.js index.html   # графики, серии, проценты, архив (43)
node tests/test-bot.js      index.html   # логика бота + сверка формул с HTML (59)
node tests/test-bot-net.js               # запросы в Supabase и Telegram (27)
node tests/check-syntax.js  index.html   # компиляция <script> без запуска
```

Тесты вытаскивают функции из HTML по имени и подставляют фиксированную дату,
поэтому при переименовании функций их надо править.

Отдельно есть smoke-тесты в настоящем браузере (Playwright): демо-режим,
отметки, виды, модалка, тема, PWA. Они не трогают боевую базу — SDK Supabase
подменяется заглушкой, запросы на `*.supabase.co` блокируются.

```bash
npm ci && npx playwright install chromium   # один раз
npm run test:e2e
```

Всё это же гоняет GitHub Actions на каждый пуш в `main`
(`.github/workflows/ci.yml`).

## Что уже сделано

Два аудита с исправлениями. Первый — технический: стабильные id привычек и
миграция истории, очередь офлайн-синхронизации, проверка `res.error`, живая
дата (раньше «сегодня» застывало на момент загрузки), экранирование, точечный
рендер вместо полной перерисовки, PWA (манифест, service worker, иконки),
экспорт и импорт JSON.

Второй — дизайн и удобство: вернули баннер демо-режима (был скрыт
`display:none!important`, и человек не знал, что данные не сохранятся) и
наполнили демо историей; переключатель звука; контраст мелких подписей;
зона касания точек в месяце; иконки под тёмную тему через `color-mix`;
связанные горизонтальные прокрутки месяца; статистика с базой («47 из 63»);
Esc и фокус-трап в модалке, свайпы, пустое состояние, отмена удаления; точки
стали `button role="checkbox"` с подписями и видимым фокусом; графики
привычек, цели, архив, годовой вид; цитата дня и снятые ложные атрибуции.

Третий заход — надёжность: smoke-тесты в настоящем браузере, проверка
синтаксиса, прогон всего этого в GitHub Actions и бот напоминаний в Telegram
(код готов, установка на сервер — за мной).

## Что осталось и сознательно не сделано

- **Стартовый набор привычек не трогали по моей просьбе.** В аудите
  предлагалось не выдавать новичку сразу девять ежедневных привычек, а дать
  выбрать три из библиотеки: при девяти метрика «дней закрыто» почти всегда
  ноль, и приложение с первого дня выглядит как провал. Решение за мной.
- **Курсор-звёздочка оставлена намеренно** — мне нравится. Она назначена всем
  элементам селектором `body.magic-cursor *` и перебивает `pointer` на кнопках
  и `text` в полях. Не «исправляй» без спроса.
- **Бот напоминаний написан, но не установлен.** Код в `bot/`: вечером шлёт
  в Telegram список несделанного за сегодня, отметить можно кнопкой в чате.
  Живёт отдельным systemd-сервисом `/opt/tracker-bot`, порт не занимает
  (длинный опрос). Чтобы включить, нужны токен от @BotFather, ключ
  `service_role` из Supabase и `user_id` из Authentication → Users —
  пошагово в README, раздел «Бот напоминаний». Web Push поверх PWA так и не
  делали: на iOS он работает только у установленного на домашний экран
  приложения.
- **Таблицу `transactions` нужно создать руками** в SQL Editor дашборда
  Supabase — SQL лежит в README, раздел «Таблица для раздела „Деньги“».
  Пока её нет, вкладка Money показывает инструкцию, остальное работает.
- **В деньгах намеренно нет** нескольких валют, счетов и бюджетов по
  категориям: без них операция добавляется в два касания. Категории заданы
  списком `MONEY_CATS` в `app.js`.
- **Бэкапы базы не включены**: нужен `SUPABASE_DB_URL` в `/opt/tracker/.env`.
  Строка берётся в дашборде Supabase по кнопке **Connect** → вкладка
  **Session pooler** (не Direct connection: он на free tier только по IPv6, а
  у VPS IPv6 нет). Хост уже известен —
  `aws-1-ap-northeast-1.pooler.supabase.com:5432`. Есть помощник
  `/opt/tracker/set-db-password.sh`, который спрашивает только пароль.
- **В Supabase нужно добавить** `https://tracker.fountaine.online/**` в
  Authentication → URL Configuration, иначе вход не завершается редиректом.
